# Импорт рецептов — формат файла

_Сделано 20 ноября 2026 (этап 9.6): `POST /api/v1/recipes/import`, `app/services/recipe_import.py`, окно «Рецепты → Импорт»._

## Формат

Один файл YAML (`.yaml`), в корне — список рецептов. Кодировка UTF-8. Пример:

```yaml
- name: Сырники
  category: Завтраки
  servings: 4              # порций в закладке → Recipe.default_servings
  cooked_weight: 600       # г, выход готового блюда; нет — берётся сумма сырого веса
  time: 30                 # минут, необязательно
  effort: easy             # easy | special
  meal_types: [breakfast]  # breakfast | lunch | dinner | snack; нет поля — любые
  keeps_days: 2
  freezable: true
  allow_half: true
  in_rotation: true
  ingredients:
    - {product: Творог 5%, amount: 400, unit: г}
    - {product: Яйцо куриное, amount: 1, unit: шт, grams: 55}
    - {product: Мука пшеничная, amount: 60, unit: г}
    - {product: Сахар, amount: 20, unit: г}
    - {product: Масло подсолнечное, amount: 20, unit: мл, grams: 18}
    - {product: Соль, to_taste: true}
  steps: |
    1. Смешать творог, яйцо, сахар и соль.
    2. Добавить муку, сформировать сырники.
    3. Обжарить по 3–4 минуты с каждой стороны.
  source: https://…     # необязательно
  notes: …              # необязательно
```

## Поля рецепта

| Поле | Обяз. | Куда | По умолчанию |
|---|---|---|---|
| `name` | да | `Recipe.name` | — |
| `category` | да | `RecipeCategory` по `search_name`, нет — создать | — |
| `servings` | да | `default_servings` | — |
| `cooked_weight` | нет | `estimated_cooked_weight` | сумма граммов ингредиентов |
| `time` | нет | `cooking_time_minutes` | — |
| `effort` | нет | `effort` | `easy` |
| `meal_types` | нет | `meal_types` | `NULL` (любые) |
| `keeps_days` | нет | `keeps_days` | 2 |
| `freezable` | нет | `is_freezable` | `false` |
| `allow_half` | нет | `allow_half` | `false` |
| `in_rotation` | нет | `in_rotation` | `true` |
| `steps` | нет | `instructions` (+ `source`, `notes` в конец текста) | — |

## Поля ингредиента

| Поле | Смысл |
|---|---|
| `product` | название товара/продукта без бренда («Творог 5%») — сопоставляется со справочником |
| `brand` | необязательно: конкретный бренд |
| `exact` | `true` — «🎯 именно этот вариант» (только вместе с `brand`) |
| `amount` + `unit` | `г`, `мл` или `шт`. Ложки, стаканы и т. п. переводятся в г/мл до импорта |
| `grams` | вес в граммах для `шт` и `мл` (КБЖУ считаются на 100 г); для `г` не нужен |
| `to_taste` | `true` — «по вкусу» (соль, специи): в состав не идёт, упоминается в шагах |

## Поведение импорта

1. **Проверка без записи (dry run)** — отчёт: что создастся, что обновится, какие ингредиенты не сопоставились.
2. **Сопоставление ингредиентов**: справочник (нечёткий поиск, как в `ProductFinder`) по `product` (+ `brand`).
   Не нашлось или неоднозначно — **не создавать молча**: показать в отчёте/UI на выбор
   (подходящий продукт / новый продукт / пропустить), как при разборе чека. Выбор запоминается на время импорта.
3. Новый продукт без КБЖУ — допустим как `kbju_missing`, но рецепт с ним не сохраняется, пока КБЖУ не введены
   (как сейчас в составе блюда) — показать список «введите КБЖУ».
4. **Повторный импорт**: рецепт с тем же `name` (без учёта регистра и «ё») — по выбору «пропустить» или «обновить».
5. Ошибки валидации — по каждому рецепту отдельно с номером и названием; остальные импортируются.
6. Интерфейс: «Рецепты → Импорт» — загрузка файла → отчёт dry run → разрешение несопоставленных → «Импортировать».

## Как сделано

- Файл передаётся текстом: `POST /api/v1/recipes/import {content, dry_run: true, choices: {}, update: []}` → отчёт
  (`recipes` — по номерам со статусом create / update / exists / waiting / error, ошибками и замечаниями;
  `ingredients` — уникальные «продукт + бренд» со статусом и кандидатами). Затем тот же файл с выбором и `dry_run: false`.
- Статусы ингредиента: `matched` — точное название продукта или товара (регистр, «ё», знаки и «3,2%»/«3.2%» не важны);
  `fuzzy` — один явно похожий (подставлен, проверьте); `ambiguous` — несколько похожих; `missing` — ничего;
  `chosen` / `skipped` — выбор пользователя. Числа в названии обязаны совпадать («Творог 5%» ≠ «Творог 9%»).
  Бренд из файла выбирает продукт среди найденных; нет такого бренда — при `exact` спрашиваем, иначе берём другой бренд.
- `choices`: ключ ингредиента из отчёта → `variant_id` или `null` (пропустить). Новый продукт заводится в окне обычным
  поиском (справочник → Open Food Facts → вручную) и выбирается — сервер продукты сам не создаёт.
- `шт` без `grams` — вес штуки товара из справочника (иначе ошибка рецепта); `мл` без `grams` — 1 мл = 1 г с замечанием.
- Повтор: тот же `name` — «уже есть», пропуск; номер рецепта в `update` — обновить (всё из файла).
- Ограничения: файл до 1 МБ, до 500 рецептов; неизвестные поля — замечание, не ошибка; `{recipes: [...]}` в корне тоже читается.
