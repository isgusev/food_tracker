# Развёртывание на Amvera: тестовый и боевой стенды

Два независимых окружения, каждое — своё приложение и своя база:

| | Тестовый | Боевой |
|---|---|---|
| Проект-приложение в Amvera | `food-tracker-test` | `food-tracker` |
| PostgreSQL | `ft-db-test` (минимальный тариф) | `ft-db-prod` (не ниже «Начального») |
| Ветка GitHub | `develop` | `main` |
| Когда разворачивается | при каждом push в `develop` | после **успешного CI** на `main` |

Названия — примеры, можно свои. Миграции схемы применяются автоматически при каждом
старте контейнера (`scripts/start.sh`); если миграция упала, контейнер не запустится —
смотрите логи в Amvera.

> Пароли, ключи и коды задаются **только в Amvera**, в git и в чат их не кладём.

## 1. Базы данных (два раза: test и prod)

1. Amvera → **PostgreSQL** → «Создать базу данных».
2. Имя проекта: `ft-db-test` / `ft-db-prod`. Тариф: для prod — не ниже «Начального» (так советует Amvera).
3. Параметры: имя базы `foodtracker`, пользователь `ft` (имя `postgres` зарезервировано), пароль — сгенерируйте:
   ```bash
   openssl rand -base64 24
   ```
4. Дождитесь статуса «PostgreSQL запущен» и откройте страницу **«Инфо»**: там внутреннее доменное имя
   для чтения-записи вида `amvera-<ваш_логин>-cnpg-ft-db-prod-rw` и порт (обычно `5432`).
5. **Только prod:** включите расписание бэкапов (бесплатно, хранятся 3 последних). Перед крупными
   обновлениями делайте бэкап вручную — «Создать бэкап».

## 2. Секреты (для каждого окружения — свои)

```bash
openssl rand -hex 32
```
→ `SECRET_KEY`.

```bash
python3 -c "import secrets; print(''.join(secrets.choice('ABCDEFGHJKMNPQRSTUVWXYZ23456789') for _ in range(12)))"
```
→ `FIRST_INVITE_CODE` (код для самой первой регистрации; на непустой базе он уже не работает).

## 3. Приложения (два раза: test и prod)

1. Amvera → «Создать проект» → приложение, имя `food-tracker-test` / `food-tracker`, тариф на ваш выбор.
   Конфиг `amvera.yml` уже в репозитории: сборка по `Dockerfile`, порт `8000`.
2. Раздел **«Переменные»** — добавьте (секреты — кнопкой «секрет»):

| Имя | Значение | Тип |
|---|---|---|
| `ENVIRONMENT` | `prod` (и для теста — так он ведёт себя как боевой) | переменная |
| `SECRET_KEY` | из шага 2 | **секрет** |
| `POSTGRES_HOST` | внутреннее имя `…-rw` из шага 1 | переменная |
| `POSTGRES_PORT` | `5432` (как на странице «Инфо») | переменная |
| `POSTGRES_DB` | `foodtracker` | переменная |
| `POSTGRES_USER` | `ft` | переменная |
| `POSTGRES_PASSWORD` | пароль базы из шага 1 | **секрет** |
| `REGISTRATION_MODE` | `invite` | переменная |
| `FIRST_INVITE_CODE` | из шага 2 | **секрет** |
| `CORS_ORIGINS` | `[]` | переменная |

   Переменные применяются после перезапуска контейнера; при сборке они недоступны — так и задумано.
3. Раздел сети/доменов — включите домен для приложения и проверьте, что адрес открывается по **https**
   (без https не будет камеры для штрихкодов и установки на телефон).

## 4. Связь с GitHub (автодеплой)

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → новый токен:
   доступ только к `isgusev/food_tracker`, права **Contents: Read-only** (Amvera только читает код).
2. Amvera → проект → **«Репозиторий»** → GitHub:
   - токен из п. 1;
   - событие: для **prod** — «Workflow runs» (деплой только после успешного CI), для **test** — «Push»;
   - секрет вебхука — придумайте любую строку;
   - целевая ветка: `main` для prod, `develop` для test;
   - скопируйте сгенерированный URL → «Применить».
3. GitHub → репозиторий → **Settings → Webhooks → Add webhook** (по одному на каждый проект):
   URL из Amvera, Content type `application/json`, тот же секрет, событие —
   «Workflow runs» (prod) или «Just the push event» (test).

## 5. Первый запуск

1. Откройте `https://<домен>/app/` → «Регистрация». Поле «Код приглашения» — `FIRST_INVITE_CODE`.
2. Вы в своей семье. Дальше: **Семья → Пригласить в приложение → «Создать приглашение»** (галочка
   «сразу в нашу семью»). Ссылка копируется — отправьте жене: она зарегистрируется по ней
   и сразу окажется в вашей семье. Код одноразовый, живёт 7 дней.
3. После первой регистрации переменную `FIRST_INVITE_CODE` можно удалить.
4. На телефоне: открыть адрес в Chrome (Android) или Safari (iPhone) → «Установить приложение» /
   «На экран „Домой“».

## 6. Как выпускать обновления

1. Новая работа — в ветке, затем слияние в `develop` → тестовый стенд обновится сам.
2. Проверили на тесте → Pull Request `develop` → `main` → после зелёного CI обновится боевой.
3. Перед обновлением, где меняется схема (новая миграция), — ручной бэкап prod-базы.

## 7. Если что-то пошло не так

- **Контейнер не стартует** — логи проекта в Amvera: чаще всего неверные `POSTGRES_*` или упала миграция.
- **«SECRET_KEY не задан»** — не добавлен секрет `SECRET_KEY` (в prod стандартный ключ запрещён).
- **Нужно откатить базу** — бэкап prod-кластера: восстановление создаёт **новый** сервис, поэтому
  после него поменяйте `POSTGRES_HOST` в приложении на новое внутреннее имя.
- **«Слишком много неудачных попыток»** — после 10 неверных паролей за 15 минут вход с этого адреса
  для этого логина приостанавливается на окно; подождите.

## Локальная разработка

По умолчанию регистрация теперь по приглашениям. Для локальной работы и `python -m scripts.seed`
добавьте в свой `.env` строку `REGISTRATION_MODE=open` — или выдайте код вручную:
```bash
python -m scripts.invite
```
